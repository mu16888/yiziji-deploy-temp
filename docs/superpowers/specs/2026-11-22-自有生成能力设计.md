# 自有生成能力 — 设计文档（增量）

- 日期：2026-11-22
- 状态：待批准
- 类型：对已有 `ai-monetization-template` 的增量设计

---

## 1. 意图与 Why

用户明确原则：OpenMAIC / Curriculum Genie / MagicSchool **只借鉴产品模式与变现链路**，最终要做**自己的产品**变现，不把核心能力绑定在任何外部开源项目上。

因此拒绝「本地起 OpenMAIC 当生成引擎」的路线（已发生的 clone/PostgreSQL 安装均搁置或撤销）。改为：**直连 DeepSeek 作为底层语言模型，自研「讲义 → 结构化课件」的生成编排**，产出完全属于本产品的 `Courseware` 数据格式。

护城河 = 自研编排逻辑 + 教育垂直理解 + 自有数据结构 + 已建成的变现内核（账本/订单/分销）。底层模型可替换（DeepSeek 只是当前选择），产品能力自有。

---

## 2. 与现有项目的边界

现有 `ai-monetization-template` 已完成并通过终审（162 tests），本增量只动两处：

1. **新增 `DeepSeekGenerationAdapter`**：实现已有 `GenerationAdapter` Protocol（`estimate` / `submit` / `status` / `result` / `cancel`），替换 mock 作为真实引擎。`estimate` 继续按 §12.6 规则本地计价（基础10/互动25/PBL40/导出5），不依赖模型估算，避免成本失控。
2. **产物数据格式 `Courseware`**：由自研编排生成，存进 `GenerationJob.result`，学生页 `/c/{share_code}` 渲染它。完全自有，不跟 OpenMAIC 的 stage DSL 兼容。

不动：账本、订单、支付、分销、后台、AIGC 合规、已有页面骨架（学生页只是换渲染数据源）。

## 3. 自研生成编排（核心）

输入：老师粘贴的讲稿 / 上传的文档（PDF/Word/Markdown/纯文本）。

```
资料摄取(Ingest) → 文本提取与清洗 → 结构化理解(LLM) → 课程大纲(LLM)
   → 逐场景生成(LLM) → 测验生成(LLM) → 讲稿/字幕(LLM) → 组装 Courseware(JSON)
   → AIGC 标识 → 存 result → 学生页渲染
```

每一步都是本产品自己的逻辑（prompt 模板 + 校验 + 失败重试 + 结构化输出 schema）。LLM 只做「按指令产出 JSON」，编排/校验/降级策略全在我们手里。

### 3.1 Courseware 数据结构（自有 schema）

```json
{
  "version": "1.0",
  "title": "...",
  "subject": "...", "grade": "...", "duration_min": 10,
  "scenes": [
    {
      "type": "slide | quiz | discussion",
      "title": "...",
      "bullets": ["..."],
      "narration": "...",
      "visual_hint": "...",
      "quiz": {"question": "...", "options": [], "answer": 0, "explain": "..."}
    }
  ],
  "aigc": {"label": "AI辅助生成", "provider": "deepseek", "model": "..."}
}
```

学生页按 `scenes` 顺序渲染：幻灯片逐页、测验可交互（选项→对错→解析）。这是完全自主的播放器，不依赖任何第三方运行时。

### 3.2 失败与降级
- 单场景生成失败**或内容为空**（标题/要点/旁白全空）→ 重试 1 次 → 仍失败则用占位场景并标记 `degraded`（学生端显示「（生成失败）」标记，不是空白页），不回滚整个任务。
- 测验阶段产出少于 3 道有效单选题 → 重试 1 次 → 仍不足则视为整篇失败（设计要 3–5 题），`CoursewareError` 触发 job failed → 全额退积分。
- **计价按课件类型、与降级无关**：积分按课件类型（basic / interactive / PBL）由本地规则预估（§12.6），单场景降级**不改变价格**，不做按成功场景数的细粒度计费（已知限制）。
- 整篇编排失败（理解 / 大纲 / 测验阶段抛错）→ job failed → 全额退积分（复用现有 `fail_job`）。
- 模型超时/限流 → worker 指数退避，超过上限转 failed 并退积分。

## 4. 资料摄取（Ingest）

- 纯文本/Markdown：直接读。
- PDF：用 `pypdf`（纯 Python，无系统依赖）提取文本。
- Word：`python-docx`。
- 文件存本地 `uploads/`（模板阶段，生产换对象存储），大小/类型白名单校验，防止恶意文件。
- 摄入结果（提取出的文本）随 job 一起进入编排，不长期留存原文件（隐私）。

---

## 5. 配置与密钥（安全）

- `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`（默认 `https://api.deepseek.com`）、`DEEPSEEK_MODEL`（默认 `deepseek-chat`）走环境变量 / `.env.local`。
- 密钥绝不进代码、不进 git、不进共享记忆、不进对话记录。
- 模型适配器可插拔：接口是「文本进 → JSON 出」，将来换豆包/通义只改配置与少量 prompt。

## 6. 测试策略

- `DeepSeekGenerationAdapter` 注入 fake HTTP client（不真调 DeepSeek），断言：
  - `estimate` 按 §12.6 规则返回，与模型无关；
  - `submit` 触发编排、`status` 映射、`result` 返回合法 Courseware schema；
  - 单场景失败降级、整体失败退款。
- 资料摄取：用最小 PDF/docx 样本验证文本提取；非法文件被拒。
- 学生页：用自制 Courseware 渲染，断言场景/测验显示正确。
- 全链路：预扣 → 编排 → Courseware → 结算 → 分享，复用现有 e2e 风格。

## 7. 非目标

- 不 fork / 不部署 OpenMAIC，不兼容其任何数据格式。
- 不做自建模型训练；DeepSeek 是黑盒 LLM，只做指令遵循。
- 不做实时语音/数字人；讲稿文本先出，配音留后续。
- 不改已有变现内核的计价与账本规则。

## 9. 总负责决定（已定，不再逐项征询）

用户授权「项目总负责、想好再推进」。以下边界由我拍板，理由随附：

| 决定 | 内容 | 理由 |
|---|---|---|
| 资料范围 | 文本/Markdown + PDF(`pypdf`) + Word(`python-docx`)，**PPTX 后置** | PPTX 解析复杂易碎，先用覆盖 90% 场景的三种格式 |
| 测验交互 | 单选 + 即时对错/解析 | 最小可用闭环，多选/填空留后续 |
| 适配器执行模型 | `submit()` 内同步跑编排，产物存 adapter registry，`status()`/`result()` 取回；失败在 adapter 内标记使 `status()` 返回 failed 触发退款 | 完全贴合现有 worker 的 queued→running→settle/fail 机制，零改动核心 |
| 同步阻塞限制 | 接受：单 worker 串行、大任务阻塞后续；文档标注，生产换真队列 | 模板阶段单任务演示足够，不为假设的规模过度设计 |
| 计价 | `estimate` 按课件类型（basic/interactive/PBL）本地规则，与模型解耦；单场景降级不改变价格，不做按场景数结算；整篇失败全额退 | 成本可控、不因模型估算波动，避免按场景计价的复杂账单 |
| 密钥 | 环境变量注入，不进代码/git/记忆/对话 | 安全底线 |
| 模型可替换 | 接口限定「文本进→JSON 出」，换厂商改配置+prompt | 不被 DeepSeek 锁定 |
