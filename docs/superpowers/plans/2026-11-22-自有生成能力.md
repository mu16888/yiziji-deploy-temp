# 自有生成能力 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用自研「讲义→结构化课件」编排 + DeepSeek 底层模型替换 mock 生成，产出完全自主的 Courseware 数据格式，不依赖任何外部开源项目。

**Architecture:** 新增 DeepSeekGenerationAdapter 实现现有 GenerationAdapter Protocol；submit() 内同步跑编排（摄取→理解→大纲→逐场景→测验），产物存 adapter 内部 registry，worker 下一轮 status()/result() 取回并结算。核心账本/订单/ worker 零改动。学生页增强渲染自制 Courseware。

**Tech Stack:** Python 3.11+, httpx, pypdf, python-docx, 现有 FastAPI/SQLAlchemy/Jinja2 栈

**Spec:** `docs/superpowers/specs/2026-11-22-自有生成能力设计.md`

## Global Constraints

- 不 fork / 不部署 / 不兼容 OpenMAIC 或任何外部开源项目；DeepSeek 仅为可替换底层 LLM。
- 所有密钥走环境变量（`DEEPSEEK_API_KEY` 等），不进代码/git/记忆/对话；测试一律用 fake client，绝不真调模型。
- `estimate` 按现有本地规则（§12.6 基础10/互动25/PBL40/导出5），与模型解耦，不随模型估算波动。
- 金额/积分整数，`GenerationJob` 计费流程（reserve/settle/refund）不改；`complete_job`/`fail_job` 逻辑不改。
- 产物 schema 自有（`Courseware`），`version="1.0"`，不依赖任何第三方运行时。
- `app/domain/**` 不 import fastapi。
- 现有 162 个测试必须全绿；新代码 TDD（失败测试先行）。
- 同步阻塞为已知限制（单 worker 串行），文档标注即可，不为此过度设计。

## Review Focus

- **密钥泄露**：任何代码、日志、异常信息里不得出现真实 key；fake client 测试不得打印请求体含 key —— 在 N1 加 `test_no_key_in_errors`。
- **计价被模型操纵**：模型返回任何 credits 数值都不影响 estimate —— N4 加 `test_estimate_ignores_llm`。
- **整篇失败退款**：编排抛错时 `status()` 返回 failed，worker 调 `fail_job` 全额退积分 —— N4 加 `test_failed_orchestration_refunds`。
- **产物 schema 完整**：Courseware 必须有 version/title/scenes，每个 scene 有 type/title， quiz 有 question/options/answer —— N3 加 `test_courseware_schema_valid`。
- **恶意文件**：摄取拒绝对非白名单扩展名/超限大小 —— N2 加 `test_ingest_rejects_bad_file`。

### Task 4: DeepSeekGenerationAdapter（协议实现）

**Files:**
- Create: `app/adapters/generation/deepseek.py`
- Modify: `app/adapters/generation/__init__.py`（注册 `"deepseek"`）
- Test: `tests/test_generation_deepseek.py`

**Interfaces:**
- Consumes: `build_courseware` (N3), `extract_text` (N2), `DeepSeekClient` (N1), `GenerationJob`
- Produces:
  - `class DeepSeekGenerationAdapter`: 实现 `estimate/submit/status/result/cancel`
  - `__init__(self, client: LLMClient | None = None, store: dict | None = None)`

**关键执行模型（总负责已定）**：
- `submit(job, spec)`：从 spec 取 `text` 或 `material_text`（已摄取文本）；调 `build_courseware`；产物存内部 `store[external_id]`；`external_id = f"ds-{job.id}"`；失败存 `store[eid]={"_status":"failed"}` 并返回 eid（让 worker 走 fail_job 退款）。
- `status(eid)`：`store.get(eid,{}).get("_status","succeeded")`。
- `result(eid)`：返回 courseware dict（含 `share_code`/`share_url`，worker 的 `_fetch_result` 会取）。
- `estimate(spec)`：**本地规则，与 LLM 完全无关**（复用 §12.6；可 import mock 的 estimate 逻辑但不得调 LLM）。
- `cancel(eid)`：标记 cancelled。

  - spec 文本来源：优先 `spec["material_text"]`，其次 `spec["text"]`；都没有则用一段默认教学文本（保证 demo 可跑，文档说明）。
  - 产物 store 用实例字典（测试注入）；真实 worker 同一实例跨 poll 使用，OK。
